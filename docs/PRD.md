# 知证：Agentic RAG + Wiki 产品需求文档

版本：1.0 · 2026-09-09 · 状态：实现前基线

## 1. 产品目标

面向企业知识维护人员与客服支持人员，把分散文档变成可核查、可持续维护的回答与知识页面。系统既能围绕问题逐步查证，也能把有价值的结论沉淀为 Wiki；原始资料更新后，旧结论应退出可信检索范围并进入复核。

核心场景：售后政策、产品说明和流程规范分散在多份资料中。用户需要查找条款、对比版本、确认结论来源；维护者需要知道哪些知识页面受新版本影响。

## 3. 用户流程

1. 维护者导入 UTF-8 Markdown / TXT，或上传受限大小的 DOCX；提供稳定 `source_key`。
2. 相同资料重复导入保持幂等；同一 `source_key` 的新内容形成新版本。
3. 用户提出问题，选择固定 RAG 基线或 Agentic RAG。
4. Agent 选择知识搜索、Wiki 搜索、原文读取工具，按证据继续查询或结束。
5. 返回回答、可解析的来源、使用模式、停止原因、耗时及调用统计；缺少依据时说明不足。
6. 维护者选择原始资料生成 Wiki 草稿，查看结构化结论与来源，显式发布。
7. 原文版本变更使相关 Wiki 失效；失效页面保留历史，但不会参与可信检索。
8. 维护者重新生成草稿、核对后发布；可查看历史与导出 Markdown。

## 4. 功能需求与验收标准

### F1 文档导入与版本管理（P0）

- 导入文本必须有标题、稳定来源键和非空内容；文件大小与文本长度有上限。
- Markdown / TXT 使用 UTF-8；DOCX 读取正文，拒绝过大的 ZIP 展开内容；不解析宏或外部资源。
- PDF/OCR 不在本期支持范围，返回明确不支持信息；不自动安装解析器。
- 采用内容哈希实现幂等；更新不覆盖旧正文，版本单调递增。
- 分块保留定位信息，检索命中可直接读取对应版本原文。
- 验收：重复导入不增加版本；更新后检索只返回当前版本；仍能读取历史来源。

### F2 检索与证据（P0）

- 中文字符与相邻字符组合、英文词项用于 BM25 索引；标题参与检索。
- 提供 `search_documents`、`search_wiki`、`read_evidence` 三个只读工具；工具参数由应用校验。
- 原始资料与 Wiki 类型明确分开；草稿与失效页面不进入 Wiki 搜索。
- 所有来源均有稳定 ID、标题、版本、定位和内容；模型不能伪造通过校验的引用。
- 验收：已知样例命中预期来源；Wiki 引用可递归追到原始片段。

### F3 Agentic RAG（P0）

- OpenAI 兼容模式下，模型根据已取得的证据自主选择工具、参数及下一步，支持多轮工具调用。
- 限制模型轮次、工具调用数、总运行时间、单次输出与累计 Token 预算；不允许无限循环。
- 记录工具选择、工具结果摘要、耗时和停止原因；不索取或存储模型私有思维链。
- 验证最终引用属于本次已获取证据；缺失、越权或失效引用不能作为可信答案返回。
- 模型失败、格式错误、超时或预算耗尽时返回明确状态与可用证据；不把摘录降级伪装成真实模型完成。
- 固定 RAG 基线复用同一检索工具和资料，用于对照。
- SSE 实时输出检索/工具/状态/最终结果事件；本期不宣称模型 Token 流式输出。
- 验收：脚本化模型测试能执行“搜索→读取→追加搜索→回答”；失败与预算分支有回归测试。

### F4 Wiki 知识维护（P0）

- 根据所选当前原文生成结构化结论，每条结论必须附原始片段引用。
- OpenAI 模式由模型生成主题内容；离线模式仅建立明确标记的原文摘录草稿。
- 草稿必须显式发布；发布时在事务内复查所有来源仍为当前版本。
- Wiki 每次更新保存修订历史及依赖；旧版不丢失。
- 原文更新在同一数据库事务中标记依赖旧版本的 Wiki 失效，检索立即排除。
- Lint 检查失效来源、缺失引用、未发布页面和页面链接问题；确定性检查不冒称语义矛盾识别。
- Markdown 可导出，包含每条结论的来源与原文版本；数据库是事务性事实存储，导出可重新生成。
- 验收：发布草稿后可搜索，原文更新后立即不可搜；重建并发布后恢复；并发发布/更新不留下可信旧页面。

### F5 操作入口与可观测性（P0）

- CLI 支持初始化/样例导入、提问、Wiki 生成/发布/检查/导出、启动服务。
- FastAPI 提供健康状态、资料、查询、SSE、Wiki 和轨迹 API，`/docs` 可直接操作。
- 查询轨迹持久化，展示公开工具活动和调用用量；日志不记录密钥或供应商完整错误正文。
- 外部 API 请求只发送用户显式导入的资料与本次问题；不自动扫描用户目录、读取项目文件或联网采集资料。

### F6 评测（P0）

- 样例资料为明确标注的虚构售后业务数据，不包含用户或企业真实数据。
- 离线回归集涵盖直接查询、跨资料、缺少依据、文档更新和 Wiki 失效。
- 报告基线/Agent 运行模式、预期来源命中、引用合法性、拒答、耗时及模型用量。
- 测试替身结果只证明控制流，离线检索命中不等于答案正确率；不填写虚构提升百分比或成本数字。
- 提供真实模型评测入口；缺少配置时明确跳过，不自动选择或购买服务。

## 5. 非功能要求

- SQLite 使用事务、外键、WAL 与有限 busy timeout；每次操作独立连接，避免跨线程共享连接。
- 文档更新与 Wiki 失效必须原子提交；发布时再次检查依赖，避免检查与提交间竞态。
- 导入、查询参数、工具参数均设大小与数量限制；来源 ID 由服务生成。
- 任意路径读取不开放给 HTTP；CLI 只读取用户指定的导入文件，拒绝 `.env` 及其变体。
- 文档内容被标记为不可信数据，不能改变工具权限；模型仅有只读检索工具，不能自行发布 Wiki 或执行代码。
- 不自动下载包、模型、浏览器或前端资源；仓库不含外部 CDN 依赖。

## 6. 架构与长期维护成本

采用模块化单体：存储/检索、模型适配、Agent 执行、Wiki 编译、HTTP/CLI 分离。模型适配采用策略接口，便于以确定性替身验证异常路径；核心存储使用标准库，便于在现有 3.9 环境测试。

LangGraph 已可用，但是否引入由编排可维护性决定，不为堆叠框架引入第二套状态；本期允许用显式有界状态循环完整实现工具调用。Milvus、Redis 和任务队列暂不引入，避免没有规模证据的服务维护成本。BM25 在单机小型语料上计算；超出该范围后需以实测推动持久化索引、向量适配与异步任务改造。

Wiki 增加了知识更新责任：必须保存原文版本、依赖与发布状态。采用数据库事务而非同时直接写多份 Markdown 文件，以免半成功更新导致页面与索引不一致。

### 9.3 切分策略与实验入口

保留默认导入 `fixed`：900 Unicode 字符窗口、120 字符重叠，窗口后部按换行和中文句号调整末端，保存精确原文 offset。通用函数校验整数参数、前进条件和有效重叠；纯空白窗口留在存储中以保证原文重建，BM25 与 Wiki 编译过滤纯空白正文。

新增 `structure` 纯预览策略：按 ATX 标题维护章节路径，识别代码围栏，在章节内按段落、有限中英文句末、字符硬上限选择边界；不跨章节重叠，返回边界原因和实际重叠数。结构元数据与原始文本分开，保持 offset 对应真实切片。尚不保证完整 Markdown、表格、HTML、DOCX 标题样式或语义解析。

`POST /api/chunk-preview` 允许用户输入不超过 20,000 字符的正文，size 200–2,000、overlap 0–500 且不超过 size/2，选择 fixed/structure 后得到真实切片与统计。预览不请求模型、不写数据库、不改变导入默认策略。已有数据仍采用 fixed，结构策略没有自动进入检索或触发重分块迁移。

验收以片段上限、向前推进、原文 slice 一致、去除重叠后完整重建、围栏内标题忽略、章节重叠边界和预览零持久化为准。**900/120 是未调优基线，结构策略效果仍需实际问题对照；片段数变化不能替代召回或答案效果验证。**

## 10. 第三轮：工程可靠性与可验证的求职展示
