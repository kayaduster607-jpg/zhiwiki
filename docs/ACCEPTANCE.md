## 2. 关键控制流

- 原文重复导入幂等，新内容保存新版本，旧片段保留定位与可读历史。
- 新 Wiki 草稿不遮蔽仍有效的发布版；新修订发布才归档旧发布版。
- 来源更新与 Wiki 失效在同一事务；发布/更新竞争后的最终状态不留下有效的旧来源页面。
- 在最后一次模型调用期间更新原文，旧 chunk 引用或依赖旧 chunk 的 Wiki 引用均被拒绝；持久化状态与返回一致。
- 脚本化模型覆盖多轮工具检索、原文读取、未知工具、无效参数、伪造引文、上下文/轮次/工具/Token 预算、缺少 usage 等分支。
- MockTransport 覆盖 HTTP 错误、超时、非 JSON、超大响应、慢速分块、响应脱敏；从不据此声称真实服务已连通。
- Wiki 编译器校验每条结论的来源属于所选原始片段，只保存草稿，发布需要独立动作。
- 文件导入拒绝 `.env*` 路径及解析后的敏感路径、目录式上传文件名、过大输入和 DOCX DTD；未读取用户 `.env`。
- 固定与结构切分均检查字符上限、推进、精确 offset 和去重叠后的完整重建；结构策略另检查标题层级、围栏内标题忽略、段落/句末边界及实际重叠。
- 预览 API 使用真实切分函数、保留原文空白，拒绝非法参数；不新增原文、Wiki 或模型调用。样例 catalog 为只读公开元数据。
- 完整样例明确标记人工虚构，重复载入幂等；同名用户 Wiki、编辑或失效页面不会被覆盖或自动重发。

问题级来源覆盖计算为 `|预期来源 ∩ 返回引用来源| / |预期来源|`，再对 23 道有预期来源的问题取均值。它不惩罚返回的额外无关来源，也不是引用精确率、片段级召回或答案正确率。20/23 表示 20 个问题覆盖了所有指定来源，并不表示 20 个问题的生成答案已判断正确。

### 4.1 三个未覆盖全部预期来源的问题

两个离线入口都出现以下结果：

| case_id | 核验主题 | 命中的预期来源 | 缺少的预期来源 | 覆盖 |
|---|---|---|---|---:|
| `gold-member-return-shipping` | 金星会员与无理由退货回寄责任 | `example:membership` | `example:shipping` | 0.5 |
| `invoice-policy-date` | 跨年补开发票与适用政策日期 | `example:invoice` | `example:refund-2025` | 0.5 |
| `quality-escalation` | QF-PENDING 材料缺口与客服交接 | `example:quality-inspection` | `example:service-escalation` | 0.5 |

三题均有有效摘录，状态为 `completed`，但缺少指定的一项依据。部分命中正文会重复相关规则，不应据此隐去严格来源清单中的缺失，也不能直接推断答案必然错误。这个结果提示：扩充语料后，固定 top 5 词法检索在多来源覆盖上仍有不足，真实 Agent 补查能否改善需要单独验证。

两个离线入口共用固定搜索与确定性摘录，耗时差不能用于宣称 Agent 更快或更好；这些单次小样例的 P95 不是生产容量数据。当前报告没有将 structure 接入入库检索，不能说明结构策略优于 fixed。完整摘录、来源和人工核验点均保留在 JSON，不填造模型正确率。
