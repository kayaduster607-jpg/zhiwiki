# 星舟商城 · 虚构知识演练资料

用于观察文档导入、引用回读、Wiki 版本和来源失效。16 份 Markdown 原文、4 页人工示例 Wiki 和评测题均为人工编写的虚构材料，不代表真实商家承诺或模型业务效果。

## 载入并检查一次

先按 [主 README](../README.md)安装依赖，从仓库根目录运行：

```bash
python -B -m zhiwiki --config config.example.json seed
python -B -m zhiwiki --config config.example.json serve --port 8875
```

打开 [http://127.0.0.1:8875](http://127.0.0.1:8875)，提问“2026年退款政策与2025年有什么区别？”，展开原文引用，再查看 sample- 前缀的 Wiki 页。默认 offline 为确定性摘录；Wiki 结论由人工编写并标记 mode=sample。

seed 的输出在本地 data 数据库，不会在 examples 目录另写一份文章。要得到 Markdown，先 wiki list 获取真实 ID，再用 wiki export 指定输出路径。

## 哪些文件会导入

`manifest.json` 是唯一的原文导入清单，列出标题、分类、更新时间、source_key 与简介。README、评测题、Wiki 定义不会被当作原文自动导入，服务启动本身也不会加载样例。

资料覆盖退款、物流、保修、产品、订单、质检、优惠、会员、支付与活动等场景。`wiki_samples.json` 保存四个人工页面，seed 先逐字核对来源摘句，再建立引用。重复载入遵循幂等规则，不覆盖同名用户页或已编辑的页面，也不自动把失效旧页重新变成可信状态。

## 演示一次来源失效

2025 政策和 2026 政策是不同 source_key，业务年份不同不等于数据库修订号不同；首次载入时两者都可以 version=1。

要观察失效，更新**同一个 source_key** 的正文，形成新修订，再检查引用旧块的 Wiki 是否需要复核。只是新增一个名字相似的文件，不会自动声明它替代旧来源。

## 评测材料怎么用

`evaluation.json` 包含 24 道虚构问题、期望来源与人工核对点。可用于检查来源覆盖与错误场景，不应把覆盖率写成回答正确率，也不能从离线摘录推断模型能力。材料含多块长文和跨文档条件，检索结果需要逐条回读确认。
